# 教職員配置與大型學校範例：實施計畫

更新：2026-10-04

## 1. 目標

將「115 學年度教職員工一覽表（姓名遮蔽）」整理為兩種可用範例：

1. **教職員配置結果範例**：保留級任導師、科任教師、行政與支援人員的資料關係，不依賴原 Excel 格式。
2. **可實際排課的大型學校範例**：轉成系統標準的 Classes、Teachers、Courses、Rooms、TeacherAvailability、FixedActivities 與 StaffAssignments。

最終體驗是：使用者在首頁下載範例，不修改即可匯入、驗證、執行排課、檢視結果與匯出，同時清楚知道哪些欄位是真實來源、哪些是演示假設。

## 2. 資料邊界

來源檔實際包含：

- 級任導師：66 筆人員配置；其中國小 54 班，幼兒園 6 班且部分班級有多位教師。
- 科任教師：70 筆，包含科目、任教年級／班級及身分備註。
- 行政與支援人員：40 筆職務。

來源檔**沒有**每週節數、學生數、教室容量、不可排時段與完整課程計畫。不可把補入的範例值宣稱為該校實際資料。

## 3. 產品邏輯分層

### A. 人力配置層

負責表示：

- 哪位教師是哪個班的級任。
- 哪位科任教師負責哪些科目與班級。
- 哪位人員具有哪個行政／支援職務。

本階段先支援「匯入已有配置、結構化檢視、匯出配置」。若要讓系統自動決定教師分工，還需另一套資格、專長、節數上限、志願與行政減授等輸入，不與時段排課偷混。

### B. 課程輸入層

將人力配置展開為結構化的「班級—科目—教師—每週節數」資料。年級範圍（如「中年級 1~5 班」）必須展開為逐班資料，並保留原始文字以便回溯。

### C. 時段排課層

在教師與課程分工已確定後，才將每週節數排入星期與節次，檢查班級、教師、教室、固定活動與工時限制。

## 4. 實施階段

### P0｜基線正確性（先做）

1. 修正 Excel 匯入時 workbook 未建立的錯誤。
2. 用真實匿名檔做回歸測試，確認三張工作表的筆數與文字不遺失。
3. 修正現有排課器與說明不一致的部分：
   - `max_continuous_period` 目前未實作。
   - `double_period` 目前未實作。
   - 固定活動目前只佔用班級，沒有佔用填入的教師。
   - 鎖定課程的每週多節資料需逐節辨識，不能鎖一節就略過整門課。
   - 目前搜尋在第一個可行解就停止，「評分最佳化」的說法需修正或真正實作。
4. 修正 30 班效能測試中專科教室參數沒有實際寫入的問題。

**P0 驗收**：所有說明中宣稱的硬限制都有正、反測試；不存在「介面顯示已支援，核心其實忽略」。

### P1｜教職員配置資料模型

1. 建立 `staffingPlan`，含 `homeroom`、`subjectTeachers`、`administration`。
2. 匯入時依工作表名與標題列偵測，不依賴色彩、合併儲存格或欄寬。
3. 同名、遮蔽名與多重職務不用姓名強制合併；使用穩定 ID 作為真實關聯鍵。
4. 幼兒園多導師是允許情境，只提示不自動刪除。
5. 提供三類表格檢視與配置結果 Excel 匯出。

**P1 驗收**：匯入範例後顯示 66／70／40 筆；匯出後再匯入，資料筆數與關係一致。

### P2｜大型可排課範例

1. 建立可重複執行的轉換程式，將「一年級 1~5 班」、「中年級」等文字展開為班級 ID。
2. 範例僅納入國小 54 班做時段排課；幼兒園資料留在人力配置範例。
3. 專科班級關係來自原檔；每週節數、班級人數、教室與不可排時段以「範例假設」明確標示。
4. 輸出檔內置中文說明行，避免範例值被誤當真實資料。
5. 在版本庫保留轉換程式與輸入範例，不手動維護兩份會逐漸分歧的 Excel。

**P2 驗收**：範例可直接匯入，所有班級、教師、課程參照都通過驗證；不存在指向不存在班級或教師的課程。

### P3｜使用者信心體驗

1. 首頁增加「下載大型學校排課範例」與「下載教職員配置結果範例」。
2. 匯入範例後顯示資料規模、來源與演示假設，不只顯示「成功」。
3. 排課過程改由 Web Worker 執行，顯示經過時間並允許取消，避免大型範例讓頁面看起來當機。
4. 結果顯示：需排總節數、已排節數、未排節數、硬衝突數、耗時。
5. 提供一鍵重置範例，避免 localStorage 舊版本影響演示。

**P3 驗收**：首次使用者可在三次點擊內完成「下載範例 → 匯入 → 排課」，且過程中介面保持可回應。

### P4｜效能與品質門禁

1. 建立由範例 Excel 發動的端到端測試，不只測人工組的 JavaScript 物件。
2. 每次 CI 檢查：範例筆數、參照完整性、排課成功率、硬衝突與耗時。
3. 參考環境下大型範例目標 30 秒內；效能門檻使用 CI 寬鬆上限，另記錄中位數，避免偶發機器抖動造成錯誤失敗。
4. 加入匯出後再讀取的 round-trip 測試。
5. 檢查前端 build、GitHub Pages 相對路徑、下載連結與行動裝置使用性。

**P4 驗收**：單元、整合、build 與 Pages smoke test 全數通過；範例排課 0 硬衝突、0 未排入，或以明確的不可行診斷失敗。

## 5. 測試矩陣

| 範圍 | 測試 |
|---|---|
| 配置簿匯入 | 三工作表、空表、缺表、欄位前後空白、多導師、匿名同名 |
| 中文班級展開 | `1~5班`、`1、3班`、`中年級`、`高年級 1~9班`、多科目分段 |
| 標準範本 | 舊範本相容、新欄位可選、空的 StaffAssignments |
| 排課硬限制 | 班級、教師、教室、不可排、固定活動教師、連堂、最大連續節數、鎖定課 |
| 大型資料 | 54 班可排性、超時、取消、不阻塞 UI |
| 匯出 | 課表 Excel、教職員配置 Excel、PDF 列印、round-trip |

## 6. 主要風險與對策

- **將配置結果誤當可自動配置輸入**：介面與文件明確區分「人力配置」與「時段排課」。
- **演示數據被誤當實校資料**：每個補值在 Excel 說明行與網頁標示「範例假設」。
- **中文文字剖析錯配班級**：轉換後產生逐筆對照報告，對每位科任比較原文與展開清單。
- **大型回溯搜尋卡住頁面**：Web Worker、可取消超時、中間進度與可行解保留。
- **匿名姓名碰撞**：不以姓名作主鍵；匿名範例以來源列 ID 關聯。

## 8. 建議順序

`P0 正確性 → P1 配置模型 → P2 可排課範例 → P3 使用者體驗 → P4 品質門禁`。

不建議先把大型範例上線再補硬限制；這會讓演示「看起來成功」，但實際課表不可信。
