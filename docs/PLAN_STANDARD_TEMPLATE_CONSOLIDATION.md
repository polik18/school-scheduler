# 標準範本整併實施計畫

更新：2026-10-04

## 1. 產品決策

首頁只保留一個範本入口：**「下載標準範本」**。

不再對使用者提供：

- 「下載大型學校排課範例」
- 「下載教職員配置結果範例」

「標準範本」本身就包含完整的排課前範例資料。使用者可以：

1. 不修改直接匯入並試跑排課。
2. 刪除部分範例列，改成小型學校資料。
3. 保留欄位與說明列，刪除所有範例列後填入自己的學校資料。

## 2. 標準範本內容

標準範本使用整理後的 60 班「排課前輸入」，不放入排課後結果。

### 工作表

1. `Classes`
2. `Teachers`
3. `Courses`
4. `TeacherAvailability`
5. `Rooms`
6. `FixedActivities`
7. `StaffAssignments`

每張資料表維持：

- 第 1 列：中文填寫說明與「範例資料可刪除」提示。
- 第 2 列：系統可識別的英文欄位名，不得刪除或翻譯。
- 第 3 列起：可直接試跑的範例資料。

### 預期規模

- 60 個國小班級（每年級 10 班）。
- 136 筆教師／支援人員。
- 678 筆課程輸入，展開後為 924 節。
- 40 筆行政與支援職務。
- 必要的普通教室、固定活動與教師不可排時段範例。

## 3. 隱私與範例命名

公開的標準範本不直接使用遮蔽後姓名。即使姓名第二字已遮蔽，職務、科目與班級組合仍可能提供額外識別線索。

轉換時改用穩定、可追蹤的中性名稱：

- `級任教師001`、`級任教師002`
- `科任教師001`、`科任教師002`
- `行政人員001`

保留班級、科目、負責範圍與職務結構，但不公開原始遮蔽姓名。如同一人同時授課與兼行政，使用同一 `teacher_id` 關聯；無法確定的同名資料不自動合併，需列入轉換報告人工審核。

## 4. 單一真實來源

避免同時維護「小範本」、「大型範例」、「程式內範本」與多個重複 XLSX。

### 建議架構

- 標準範本生成程式：`scripts/build-standard-template.mjs`
- 唯一公開產物：`public/school-scheduler-template.xlsx`
- 內部轉換對照報告：`tests/fixtures/generated/standard-template-report.json`
- 匿名來源檔：移到 `tests/fixtures/source/`，不由 Vite 複製到正式站。

現有 `src/template.js` 中的小型範例不再是第二份資料來源。首頁的「下載標準範本」改為下載上述靜態檔。

## 5. 介面調整

1. 刪除「下載大型學校排課範例」連結。
2. 刪除「下載教職員配置結果範例」連結。
3. 保留單一「下載標準範本」按鈕。
4. 按鈕旁說明：
   - 「內含 60 班可直接試跑的範例資料」。
   - 「可刪除範例列後填入本校資料」。
   - 「請保留英文欄位列」。
5. 工作區的「下載範本」使用同一檔案，不產生另一份內容。

## 6. 實施步驟

### S1｜整併產生管線

- 將現有大型範例轉換程式改名與重構為標準範本產生器。
- 加入中性姓名轉換與 ID 穩定性檢查。
- 只輸出 `public/school-scheduler-template.xlsx`。
- 建立來源文字→班級展開對照報告，但不對外公開姓名。

### S2｜移除重複與對外範例

- 移除 `public/examples/large-school-schedule-demo.xlsx`。
- 移除 `public/examples/staffing-result-demo.xlsx`。
- 移除公開的轉換報告。
- 將必要的回歸測試資料移到 `tests/fixtures/`。
- 盤點並刪除根目錄與 `templates/` 中的舊重複範本，確保只有一份 canonical 產物。

### S3｜前端改為單一下載入口

- 移除兩個額外範例連結。
- 將首頁與工作區的範本按鈕都指向 `./school-scheduler-template.xlsx`。
- 刪除前端內重複生成整份範本的邏輯。
- 更新文案，告訴使用者可直接試跑或刪除範例列。

### S4｜回歸與 E2E

- 標準範本必須通過 `validateInput`，錯誤數為 0。
- 匯入後應顯示 136 師／60 班／678 課。
- 排課後應為 924 節／0 pending／0 硬衝突。
- 本機參考環境目標 30 秒內。
- E2E 改為從「下載標準範本」下載實際檔案，再將下載檔上傳排課，驗證下載與匯入的是同一份產物。
- 加入「刪除範例資料、保留標題列」的空範本檢查，確認系統會給出清楚的空資料驗證訊息。
- 另建立不對外下載的 60 班與 72 班壓力資料：60 班是正式容量門禁；72 班用來觀察超時、取消與部分結果行為。
- 60 班門禁不只檢查班級數，必須含科任跨班、固定活動、教師不可排、連續節數與教室競爭，避免只用簡單單班課程宣稱支援 60 班。

### S5｜部署

- 執行單元測試、大型範本測試、production build 與本機 Chrome E2E。
- 提交並推送 `main`。
- 等待 Test 與 Deploy GitHub Pages workflows 成功。
- 對正式站執行線上 E2E。
- 確認頁面上只剩一個範本下載入口。

## 7. 驗收條件

1. 首頁與工作區只出現「下載標準範本」。
2. 正式站不再發佈兩份額外範例與姓名對照報告。
3. 標準範本不修改即可成功排出 924 節，無 pending。
4. 公開範本不含原始遮蔽姓名，只使用中性範例名稱與穩定 ID。
5. 每張表的說明列清楚告知「範例列可刪、英文欄位列須保留」。
6. 標準範本只有一個產生來源與一個公開檔案。
7. 單元、整合、build、本機 E2E、GitHub Actions、Pages 線上 E2E 全數通過。
8. 60 班實際限制資料必須在預設 30 秒內完成、0 pending、0 硬衝突；72 班即使超時也必須可取消、保留可行部分結果且不使介面當機。

## 8. 不在本次範圍

- 不移除教職員配置匯入與匯出功能。
- 不將排課後結果放入標準範本。
- 不在此階段新增自動教師分工求解器。
- 不改變現有課表 Excel、PDF 與教職員配置結果匯出格式。
