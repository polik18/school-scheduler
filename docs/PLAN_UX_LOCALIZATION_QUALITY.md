# 下一階段實施計畫：中文化、排課透明度、動畫、教學與專業介面

更新：2026-10-04

## 1. 階段目標

將目前「能匯入、能排課、能匯出」的工具，提升為台灣學校教學組能理解、敢使用、能追查結果的專業排課產品。

本階段不只換色或加動畫，而是同時解決：

1. 排課中沒有清楚進度感。
2. 「品質指標」是什麼、數字代表什麼，使用者無法理解。
3. 排課演算法與能力邊界沒有說明。
4. Excel 欄位、布林值、星期與匯出結果仍大量使用英文或程式內部名稱。
5. 缺少完整使用教學與錯誤排除說明。
6. 工作區、排課中狀態與課表結果的視覺層級不夠專業。
7. 現有 60 班範例只有 924 節，平均每班約 15.4 節，尚不是台灣國小的完整每週課程情境。

## 2. 研究與現況審計

### 2.1 目前排課演算法

依 `src/model/solver.js` 實際程式，目前是自訂的限制滿足搜尋，不是機器學習或生成式 AI：

1. 將 `weekly_period` 展開成逐節任務；連堂課組成長度 2 的任務。
2. 先放入使用者鎖定的時段。
3. 用 MRV（Minimum Remaining Values，最少剩餘值）優先選擇候選時段最少的課程。
4. 過濾班級、教師、專科教室、固定活動、教師不可排、每日上限與連續節數等硬限制。
5. 放入候選時段；若後續無解，回溯並嘗試下一個時段。
6. 找到第一個完整可行解即停止；若超時，保留目前已找到的最完整部分解。

因此現有系統可宣稱「搜尋符合硬限制的可行課表」，但不能宣稱「AI 最佳化」或「全域最佳課表」。Google OR-Tools 將排班類問題建模為限制滿足／最佳化問題，CP-SAT 可作為未來性能與軟限制求解的對照基準，但不在未比較 bundle 大小、WASM 啟動時間與瀏覽器相容性前盲目替換現有核心。

### 2.2 目前品質指標

`scoreSchedule()` 目前只檢查「同一班、同一科目、同一天出現多節」，每多一節扣 30 分。

- 0 代表沒有觸發這個單一軟限制。
- 負數越小，代表同科同日重複越多。
- 它不是百分比、不是及格分數，也沒有反映所有教學品質。
- 搜尋在第一個完整解即停止，因此目前數字是「結果檢查值」，不是演算法真正最佳化後的分數。

直接顯示「品質指標 -1230」對使用者沒有可解釋性，應拆分成完成度、硬衝突與軟限制品質。

### 2.3 動畫與可存取性

W3C WCAG 要求狀態訊息可被輔助科技感知，且來自互動的非必要動畫應可停用。因此排課動畫必須：

- 有 `role="status"` / `aria-live` 的文字狀態，不能只靠動畫。
- 遵守 `prefers-reduced-motion`；減少動畫時改為靜態進度視覺。
- 不閃爍、不快速大幅縮放、不使用無關的裝飾動畫。
- 不顯示虛假的精確百分比。

參考：[W3C 狀態訊息](https://www.w3.org/WAI/WCAG22/Understanding/status-messages.html)、[W3C 互動動畫](https://www.w3.org/WAI/WCAG22/Understanding/animation-from-interactions.html)。

### 2.4 台灣國小擬真資料

課程節數不應憑印象填寫。下一階段應以教育部「十二年國民基本教育課程綱要總綱」為法規基線，再以公開的學校課程計畫核對實務科目與彈性學習節數。

參考：[教育部課程綱要總綱](https://edu.law.moe.gov.tw/LawContent.aspx?id=GL002057)、[CIRN 十二年國教課程綱要](https://cirn.k12ea.gov.tw/TWELVE/index.aspx)。

## 3. 目標體驗

### 3.1 排課中

點選「開始排課」後，不顯示半成品課表，而是進入獨立的「排課進行中」卡片：

- 五日課表小格以溫和的 opacity/transform 動畫依序填入，表達正在尋找組合。
- 顯示真實經過時間、目前最佳部分解 `X / 總節數`、搜尋節點數與「取消」。
- 進度文字使用真實 Worker 訊息，不用伪造的 10%→80%→100%。
- 超過 10 秒時顯示「大型資料需要較多搜尋，頁面仍可正常操作」。
- 開啟減少動畫時，改為靜態網格、真實數字與文字狀態。

### 3.2 排課完成

結果頂部改為三個清楚的門禁：

1. **排課完成度**：`924 / 924（100%）`。
2. **硬衝突**：班級、教師、教室、鎖定與固定活動衝突數；正式成功必須為 0。
3. **課程分散度 0–100**：把現有「同科同日重複」軟限制正規化，並顯示扣分明細。

「分散度 100」只代表目前已定義的軟限制沒有扣分，不代表這是唯一解或全域最佳解。使用者可展開「如何計算」查看公式與逐項明細。

### 3.3 課表檢視

不再一次渲染 60 張巨型課表。

- 預設只顯示一個班級／教師／教室，使用搜尋下拉切換。
- 上方固定顯示對象名稱、總節數、衝突數與操作。
- 科目用穩定、低飽和色彩區分，但不只靠顏色傳達科目。
- 使用系統繁體中文字體堆疊，取消不必要的全大寫英文 eyebrow。
- 列印／PDF 使用獨立列印樣式，不拿螢幕卡片勉強列印。

## 4. Excel 繁體中文化契約

### 4.1 輸入欄位

匯入器新增雙語 alias，舊英文範本繼續可用，新標準範本改為中文標題：

| 資料表 | 新中文欄位 |
|---|---|
| 班級 | 班級代碼、年級、班級名稱、學生數、導師代碼、備註 |
| 教師 | 教師代碼、姓名、主要領域、每日最多節數、最多連續節數、身分備註 |
| 課程 | 班級代碼、科目、教師代碼、每週節數、教室類型、是否連堂 |
| 教師可排時段 | 教師代碼、星期、節次、是否可排、原因 |
| 教室 | 教室代碼、教室類型、容量 |
| 固定活動 | 活動名稱、星期、節次、班級代碼、教師代碼 |
| 行政職務 | 處室／單位、職稱、教師代碼、姓名、備註 |

值也中文化：

- `Mon` 至 `Sat` 改為可填「星期一」至「星期六」，匯入時正規化為內部代碼。
- `TRUE/FALSE` 改為「是／否」，同時相容真假值、1/0、Yes/No。
- `normal/none` 改為「普通教室／不限教室」。
- 驗證錯誤使用中文欄位名，不回報 `weekly_period` 或 `room_required`。

### 4.2 匯出欄位

使用者可見的 Excel 不匯出 `unit/status/day/room_id/locked/manual` 這些內部欄位。改為：

`班級、科目、教師、星期、節次、教室、是否鎖定、是否人工調整`。

若除錯需要原始欄位，可另建「技術資料」工作表，預設不匯出或明確標示為技術用途。

## 5. 使用教學架構

### 應用程式內

- 首次使用者看到可略過的 4 步驟導覽：下載範本、修改資料、匯入驗證、排課與匯出。
- 右上角固定「使用說明」入口，導覽關閉後仍可重開。
- 每個設定旁有一句「這會影響什麼」，而不是只顯示欄位名。
- 錯誤診斷可導回範本工作表與中文欄位。

### 完整說明頁

1. 5 分鐘快速上手。
2. 每張 Excel 工作表與欄位字典。
3. 鎖定、連堂、固定活動、教室類型與教師可排時段範例。
4. 排課演算法圖解與能力邊界。
5. 完成度、硬衝突與分散度的計算方式。
6. 常見錯誤與排除方法。
7. 瀏覽器本機運算、localStorage 與隱私說明。

## 6. 擬真 60 班標準範本

### 資料原則

- 每年級 10 班，維持 60 班規模。
- 節數依教育部課綱與公開學校課程計畫核對，不用現有「級任國語 3／數學 3／專科大多 1」的簡化值充當完整課表。
- 包含國語、數學、生活課程／社會／自然、英語、藝術、綜合、健康與體育、本土語、彈性學習等實際類別。
- 反映低、中、高年級節數差異。
- 專科教師跨班、行政減授、領域會議、固定活動、專科教室數量都要真正影響可排時段。
- 人員名稱仍使用中性虛構名稱，不將原始或遮蔽姓名放回公開範本。
- 增加「範例資料說明」工作表，列出真實來源、合成假設與不可當成實校資料的邊界。

### 性能前置工作

完整國小每週課表的節數會明顯高於現有 924 節，因此不先擴充 Excel 就宣稱成功。先執行求解器性能 spike：

1. 以整數 slot ID 與 bitset 取代高頻字串 key。
2. 增量維護候選集與教師連續節數，避免每層重新掃描全部時段。
3. 避免每層 `filter()` 複製所有剩餘任務。
4. 增加搜尋節點、回溯數、最佳完成度與記憶體量測。
5. 與 [Google OR-Tools CP-SAT 排程建模](https://developers.google.com/optimization/scheduling/employee_scheduling) 進行概念驗證；僅在瀏覽器整合成本可接受且實測顯著優於自訂求解器時才轉換。

## 7. 實施里程碑

### U0｜當前基線封存

- 完成現階段 60 班單一標準範本的 commit、CI、Pages 部署與線上 E2E。
- 封存首頁、工作區、排課中、排課結果四組視覺基準圖。
- 記錄 60 班 924 節的時間、搜尋節點與記憶體基線。

### U1｜Excel 中文化

- 建立中英欄位 alias schema、星期／布林／教室值正規化。
- 標準範本改為中文標題與中文值。
- 匯出移除內部英文欄位，改為完整繁體中文。
- 舊英文範本回歸測試仍須通過。

### U2｜Worker 真實進度與動畫

- Solver 增加受控進度 callback，Worker 每 200–250ms 最多回報一次。
- 進度訊息包含 `bestPlaced/total/nodes/backtracks/elapsedMs`。
- 實作排課中卡片、課表小格動畫、真實數字、取消與 reduced-motion 樣式。
- 以輔助科技驗證狀態訊息不會過度重複播報。

### U3｜品質模型與演算法說明

- 將單一 `score` 改為 `qualityReport`：完成度、硬衝突、分散度、扣分明細與公式版本。
- 新增「如何排課」及「如何評分」展開說明。
- 所有 README、UI 與匯出報告只宣稱實際已實作的限制與評分。

### U4｜專業介面與課表重設計

- 建立設計 token：字型、字階、8px 間距、色彩、邊框、焦點、狀態與列印規則。
- 簡化首頁英文裝飾與過大標題，改為台灣校務工具的清楚層級。
- 工作區改為進度導航，重要操作位置穩定，不因狀態切換造成版面跳動。
- 課表改為單對象搜尋／切換，加入科目圖例、調課狀態與獨立列印樣式。
- 360px、768px、1440px 視窗做視覺回歸。

### U5｜使用教學

- 實作可略過、可重開的首次導覽。
- 建立完整使用說明頁、Excel 字典、演算法與品質指標說明。
- 針對「教師不存在」、「班級不存在」、「無專科教室」、「限制過緊」提供中文修正範例。

### U6｜擬真資料與求解器性能

- 完成課綱節數研究與資料來源紀錄。
- 先產生 6 班小型擬真資料驗證課程語意，再擴展到 60 班。
- 完成求解器性能 spike 後才將完整節數寫入公開標準範本。
- 保留 60 班正式門禁與 72 班壓力門禁。

### U7｜可存取性、E2E 與部署

- 鍵盤、焦點、色彩對比、狀態訊息、reduced motion 與列印檢查。
- E2E 覆蓋中文 Excel 下載→匯入→進度→完成→分數說明→課表切換→匯出。
- 視覺回歸覆蓋首頁、工作區、排課中、成功、超時與衝突狀態。
- CI、GitHub Pages 與正式站線上 E2E 全數通過後才結案。

## 8. 驗收條件

1. 排課中有真實進度、經過時間、取消、非虛假動畫與 reduced-motion 模式。
2. 不再單獨顯示無說明的負數「品質指標」。
3. 使用者可在介面內理解排課演算法、硬限制、軟限制與非全域最佳的邊界。
4. 新標準範本與使用者可見匯出全部使用繁體中文；舊英文範本仍可匯入。
5. `TRUE/FALSE`、`Mon/Fri`、`normal`、`unit/status/locked/manual` 不再出現於一般使用者工作流。
6. 應用程式內有快速導覽，並有可隨時重開的完整使用說明。
7. 課表預設只渲染一個對象，視覺層級、手機、桌面與列印都通過回歸。
8. 擬真範例的每週節數有權威來源與假設明細，不再以 924 節簡化資料宣稱完整國小課表。
9. 擴充後的 60 班擬真資料必須在目標時間內完成且 0 硬衝突；目標時間由 U6 性能 spike 實測後凍結，不先製造無證據數字。

## 9. 執行順序與相依性

`U0 基線 → U1 Excel 中文化 → U2 進度動畫 → U3 品質／演算法透明 → U4 介面 → U5 教學 → U6 擬真／性能 → U7 總驗收`。

U1–U3 先建立資料與說明契約，U4 才重設計介面，避免先畫漂亮畫面後又因進度與分數資料結構重做。U6 必須先解決性能，再擴張為完整每週課程範例。
